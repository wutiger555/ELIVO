## 1. 為什麼信任是產品功能，而不是法務工作

2025–2026 年，AI 會議工具的訴訟集中在三個點：

1. **供應商把錄音用於自己的目的（訓練）**，因而被視為「第三方竊聽者」：
   - Otter 案：2026/8 法院駁回 Otter 的部分駁回訴訟動議。
   - Granola 案：2026/7 起訴，而且 Granola 是 bot-free。
2. **其他與會者不知情**：Granola 的行銷文案「other people…won't know it's there」被原告直接引用。
3. **聲紋等生物特徵**：Fireflies 兩件 BIPA 案。

另外，Teams 與 Google Meet 正在封鎖第三方 bot，多所大學與企業禁用 AI 筆記工具。**信任本身就是 ELIVO 的差異化。**

## 2. 各地法規重點

| 地區 | 錄音同意 | 資料保護 | 對 ELIVO 的含意 |
|---|---|---|---|
| **台灣** | 通保法 §29(3)：通訊參與者錄音、或經一方同意，且非出於不法目的，即不違法。刑法 §315-1 處罰「無故」竊錄 | 個資法：2023 年修正提高罰則；2025 年修正（2025/11 公布，施行日由行政院定）新增事故通報個資會的義務；個資會尚在籌備（待驗證） | 使用者本人必須是參與者，因此需要 presence gating；ELIVO 定位為「受託者」 |
| **美國** | 聯邦法採一方同意；CA、DE、FL、IL、MD、MA、MT、NV、NH、PA、WA 須全體同意 | BIPA（IL）、Colorado HB24-1130（聲紋） | 以全體告知為預設；聲紋採 opt-in，並附書面同意與公開保存政策 |
| **EU** | 德國 §201 StGB 等實質上須全體同意 | GDPR：需合法基礎與 DPIA；用於識別個人的聲紋屬 Art. 9 特殊類別資料；台灣未取得適足性認定，跨境傳輸需 SCC | **AI Act Art. 5(1)(f)：職場情緒辨識自 2025/2/2 起禁止**；Art. 50 透明義務自 2026/8/2 起適用 |
| **日本** | 參與者錄音一般合法（待驗證） | APPI 2026 修正（2026/7 公布，約 2028 年施行）：導入罰款，新增生物特徵類別 | 第二市場；需設日本資料區 |
| **新加坡** | 無明文禁止參與者錄音 | PDPA：組織錄音需告知與同意（可為推定同意） | 東南亞 hub |
| **中國** | — | PIPL：生物特徵需單獨同意；跨境傳輸需同意 | **Phase 1 不服務** |

## 3. Compliance-by-Design 清單

### 3.1 資料使用

- [ ] **不以客戶內容訓練或微調共用模型**：預設關閉，管理員可在整個 workspace 強制；寫入 ToS 與 DPA。
- [ ] 次處理者（ASR、LLM 供應商）一律簽 zero-retention 或不訓練條款；公開次處理者清單。
- [ ] 使用者的修正（例如 ledger 修正）只用於該使用者或 workspace 本身。

### 3.2 告知與同意

- [ ] 錄製中徽章常駐，無法完全隱藏。
- [ ] 一鍵把告知文字貼到會議聊天室；可設為預設自動貼上，組織可強制開啟。
- [ ] 面對面會議：第二螢幕與 Display 上有看得到的「ELIVO 運作中」指示。
- [ ] 在全體同意的司法管轄區（依使用者設定的地區或與會者網域推斷），告知為強制。
- [ ] 提供與會者「請求暫停或刪除」的連結。
- [ ] **行銷永不使用「隱形」、「不被發現」等字眼。**

### 3.3 Presence Gating

- [ ] 只在擁有者本人參與時擷取；不自動加入使用者沒有參加的會議。
- [ ] Display：偵測擁有者離席（例如裝置配對的手機或 Mac 離開）時自動停止。

### 3.4 生物特徵

- [ ] 預設只做 diarization（我／他人、說話者 A/B），**不建立持久聲紋**。
- [ ] 聲紋辨識若將來推出：逐人 opt-in，附書面同意（BIPA 格式），並公開保存與銷毀政策。

### 3.5 AI Act 與情緒

- [ ] 任何市場版本都**不做**以語音或臉部推論情緒。
- [ ] 若做文字語氣標記，需標示「文字推論」，而且不針對個人評分。
- [ ] Art. 50：UI 清楚標示 AI 生成的內容。

### 3.6 保存與刪除

- [ ] 預設不保存音訊（轉錄後即丟棄）；如需保存，必須 opt-in。
- [ ] 保存期可設定（30、90、365 天或永久），可由 workspace 管理員統一設定。
- [ ] 刪除會連動 embedding、索引與備份（備份在 N 天內輪替清除）。
- [ ] **Ephemeral mode**：逐字稿不落地，只保留使用者確認過的決策與待辦。

### 3.7 資料落地與供應鏈

- [ ] 台灣區優先（GCP asia-east1）；之後依序開日本、EU、美國區。
- [ ] 金融客戶：資料與備份留在台灣（金管會委外規範）。
- [ ] 政府、金融、關鍵基礎設施的版本：不使用中國來源的模型、SDK 或雲端（資安法）；維護 SBOM 與模型登記表。

### 3.8 資安與認證路線

| 時點 | 項目 |
|---|---|
| Phase 1 | 加密（傳輸與靜態）、最小權限、稽核日誌、弱點掃描、事件應變計畫（個資法通報、GDPR 72 小時） |
| Phase 2 | Vanta 或 Drata → **SOC 2 Type I → Type II**（6–9 個月）；SSO／SCIM；滲透測試 |
| Phase 2–3 | **ISO 27001**（台灣與日本企業更重視）；ISO 27701:2025（隱私） |
| Phase 3 | ISO 42001（AI 管理，EU 與金融業客戶）；BYOK／KMS；地端版本 |

### 3.9 Connectors

- [ ] OAuth 最小範圍；檢索時遵守來源系統的權限（permission-trimmed）。
- [ ] 每張卡片標示來源，讓使用者清楚知道 ELIVO 讀了什麼。
- [ ] 可排除特定資料夾或標籤（例如「HR」、「法務」）。
