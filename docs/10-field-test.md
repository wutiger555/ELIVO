# 實際會議測試：會前準備與會後分析

第一次用真實、取得同意的會議測 ELIVO（2026-10-01，大型會議、Mac 單機收音）。
目的：量出大會議室的辨識品質，找出最大的問題，並用錄音比較 Breeze-ASR-25 與 Qwen3-ASR（研究見 `research/E-far-field-and-multi-device.md`）。

## 會前（10 分鐘）

1. **更新並啟動**：`bin/elivo restart`（或雙擊 `ELIVO.command`）。執行期間 Mac 不會閒置睡眠；請接上電源。
2. **術語表最重要**。合成測試中，有術語表時專有名詞辨識對的數量大約是沒有時的兩倍。
   - 建一個 Space（客戶或專案名稱），在 Space 設定填術語表，一行一個：
     - 與會者全名（例如「林宗翰」；系統也會自動比對名字「宗翰」）
     - 公司名、產品名、系統名、專案代號
     - 英文縮寫（SLA、POC、KPI…）
   - 大約 20–40 個最重要的詞就好；太長時系統會優先用最近提到的。
3. **麥克風**：
   - Mac 放在桌子中間、靠近最常說話的人；不要蓋住鍵盤兩側（內建麥克風在那裡）。
   - 系統設定 → 聲音 → 輸入：選內建麥克風，輸入音量調高（約 80–90%）。
   - 在「設定後開始」頁看音量條，請離最遠的人說一句話，確認有反應。
4. **告知與會者**：開始後畫面上方有「複製告知文字」，貼到會議通知或口頭說明。
   不希望被記錄時可以隨時暫停；會後可以刪除錄音或逐字稿。
5. **開始**：在那個 Space 裡按「開始錄音」（會自動歸類、帶入術語表），錄音預設保存。

## 會中

- 看到人名或術語一直被聽錯：右上角「會議資料」（齒輪）→ 術語表補上，之後立即生效。
- 逐字稿上有虛線底線的詞是自動校正過的，滑鼠移上去看原本辨識成什麼。
- 需要離開或談敏感內容：按「暫停」。

## 會後

1. 確認視窗：勾選決策與待辦，**保留錄音**開著（要拿來分析）。
2. 簡單記下印象：哪些地方最不準（誰說話、什麼距離、什麼詞）。
3. 分析（我來跑）：
   ```bash
   cd services/realtime
   ~/.venvs/elivo-asr/bin/python -m eval.asr_compare ~/ELIVO-data/audio/<會議 id>-me.flac --glossary <術語表檔案>
   ```
   沒有標準答案時會輸出兩個模型的逐段結果並列比對。要算錯誤率：挑 3–5 分鐘，
   把 ELIVO 的逐字稿修正成正確版本（會議頁可以直接改），存成 ref 檔再跑一次（加 `--ref`）。
4. 用完不需要時，在「錄音檔」頁刪除。

## 已知限制

- 所有現場的聲音都標成「我」（Mac 麥克風一軌）；分辨說話者要等 diarization（`research/D-speaker-diarization.md`）。
- 會議記錄與「決策不同」「術語候選」的判斷會把逐字稿送到 ICA（已確認這場可以）。
- 合成測試的數字（MER、術語召回率）只能看方向，真實會議才算數。
